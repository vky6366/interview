# Databases Interview Guide

Understanding database architectures is crucial for backend and AI engineering roles. This guide covers the major paradigms and specific technologies you are likely to be asked about.

---

## 1. SQL vs. NoSQL

The most fundamental database interview question.

### SQL (Relational Databases)
*   **Structure:** Data is stored in tables with rows and columns. Schemas are rigid and predefined.
*   **Relationships:** Highly structured relationships between tables using Foreign Keys.
*   **Query Language:** Uses standard SQL (Structured Query Language).
*   **Scaling:** Vertically scalable (scaling up by adding more CPU/RAM to a single server).
*   **Best for:** Complex queries, multi-row transactions, strict data integrity (ACID compliance), and financial/accounting systems.
*   *Examples:* PostgreSQL, MySQL, Oracle, SQL Server.

### NoSQL (Non-Relational Databases)
*   **Structure:** Data is stored in various formats: Document (JSON-like), Key-Value, Wide-Column, or Graph. Schemas are dynamic/flexible.
*   **Relationships:** Denormalized data. Relationships are often nested within the documents themselves rather than split across tables.
*   **Scaling:** Horizontally scalable (scaling out by adding more servers to a cluster).
*   **Best for:** Rapid development, unstructured/semi-structured data, huge volumes of data, and high read/write velocity.
*   *Examples:* MongoDB (Document), Redis (Key-Value), Cassandra (Wide-Column), Neo4j (Graph).

## 2. Key Database Technologies

### PostgreSQL (Postgres)
An incredibly powerful, open-source object-relational database system.
*   **Why it stands out:** It is highly compliant with SQL standards, extremely reliable, and supports advanced features like complex indexing, full-text search, and geographic data (PostGIS).
*   **In AI/ML:** It is heavily used in modern AI stacks because extensions like `pgvector` allow it to act as a fully functional Vector Database right alongside your standard relational data.

### MongoDB
The most popular NoSQL document database.
*   **How it works:** Stores data in flexible, JSON-like documents (BSON). The fields can vary from document to document, making it very easy to change the structure over time.
*   **Why use it:** Great for prototyping, content management systems, user profiles, and situations where the data model is evolving rapidly and you don't want to deal with complex migrations.

### Vector Databases (Qdrant, Pinecone, Chroma)
Essential for generative AI applications (like RAG).
*   **What they do:** They are optimized to store high-dimensional vectors (embeddings) generated by AI models.
*   **How they work:** Instead of searching for exact keyword matches, they use indexing algorithms (like HNSW) to perform **similarity search**. They find the vectors in the database that are mathematically closest (e.g., using Cosine Similarity) to the user's query vector.
*   **Use case:** Semantic search, recommendation systems, and providing context to LLMs.

## 3. Advanced Database Concepts (Bonus Points)

Mentioning these concepts will show you have a deep architectural understanding of databases.

### ACID Properties
A set of properties that guarantee database transactions are processed reliably (primarily applied to SQL databases).
*   **Atomicity:** "All or nothing." A transaction is fully completed, or not executed at all.
*   **Consistency:** The database must remain in a valid state after any transaction (obeying all rules and constraints).
*   **Isolation:** Concurrent transactions execute independently without interfering with each other.
*   **Durability:** Once a transaction is committed, it remains in the system even in the event of a crash/power loss.

### CAP Theorem
A concept for distributed systems stating that a system can only guarantee **two** of the following three properties simultaneously:
*   **Consistency:** Every read receives the most recent write or an error.
*   **Availability:** Every request receives a non-error response (but it might not be the most recent data).
*   **Partition Tolerance:** The system continues to operate despite network failures dropping messages between nodes.
*(For example, MongoDB typically favors Consistency and Partition Tolerance - CP, while Cassandra favors Availability and Partition Tolerance - AP).*

### Indexing
A data structure technique used to quickly locate and access the data in a database.
*   *How it works:* It's like the index at the back of a book. Instead of scanning every single row in a table to find a user (O(N) time), an index (often a B-Tree) allows the database to find the user in O(log N) time.
*   *Trade-off:* Indexes drastically speed up `READ` operations but slow down `WRITE/UPDATE/DELETE` operations (because the index must be updated every time the data changes), and they consume additional storage space.
